# Auto Forge：构建与可靠性规范

状态：M1 实现约束。此文不承诺真实 Agent 或连接器已经完成。

## 1. 产品边界

最终目标是让需求进入后，产品、开发、测试角色根据同一份有版本的上下文协作，
由平台管理任务状态、权限、审计和交付证据。消息调度器是入口与反馈通道，不应成为
绕过审批执行代码的入口。Agent 只提出或执行被授权的步骤，不能自行批准发布。

M1 只验证可靠的控制平面。真实角色将复用任务领取和结果协议，但需要增加不同能力和
严格结果合同，不能把 `kind: simulation` 改名为真实证据。

## 2. 组件职责

| 组件 | 责任 | 不允许做的事 |
| --- | --- | --- |
| API | 认证、输入校验、命令幂等、调用状态机 | 根据自由文本执行命令 |
| PostgreSQL | 状态、不可变输入、尝试记录、事件、收据 | 被 Worker 直接写入绕过状态机 |
| Dispatcher | 消费 outbox，按固定 recipe 建立下一任务 | 读取日志中的 PASS 来决定交付成功 |
| Worker | 领取、心跳、按租约提交类型化结果 | 自行推进交付、修改项目范围、批准自身结果 |
| 操作台 | 创建输入、确认就绪、展示快照、发控制命令 | 持久保存 API 令牌或伪装完整 Agent 能力 |

API 与 Dispatcher 当前在一个进程，Worker 是独立进程。模块化单体用于减少部署复杂度；
数据库不是内存缓存，多进程调度通过行锁和唯一约束协调。暂不引入外部消息中间件。

## 3. 实体与输入合同

- Project：本地管理员可见的逻辑项目。目前不是权限隔离租户。
- Source：`project + connector + externalId + sourceRevision` 唯一；同版本不同正文拒绝。
- Requirement：revision 1 不可变快照，包含范围、需求条目、验收条目、来源引用和阻塞问题。
  重复 ID、无验收覆盖或跨项目来源均拒绝。M1 不支持在线编辑；变更需创建新快照。
- Delivery：绑定 ready 需求及其 canonical SHA-256 digest，模式仅 `simulation`。
- Job：一个 recipe 阶段，每个 `delivery + step_index` 最多一个。重试不是新增阶段任务。
- Attempt：每次领取生成记录，保留 ordinal、epoch、Worker 与结局。
- Event / Outbox / Inbox：业务事件、投递状态、消费者去重记录。
- CommandReceipt：命令摘要和已提交响应，支持网络丢响应后的安全重试。

对象属性按键排序计算摘要，数组保持顺序。未知字段默认拒绝。
`GET /v1/contracts` 返回由实际 Zod 合同生成的 JSON Schema。
目前尚未定义真实项目 Manifest、代码候选、测试证明或 EvidenceBundle 的生产合同。

## 4. 状态规则

需求：`draft → ready`。存在 blockingQuestions 时不可就绪。

交付：`queued → running → simulation_completed`；非终态可进入 `failed` 或 `cancelled`。
控制状态独立为 `active / paused`。终态不可恢复、重开或覆盖。

任务：`queued → running → succeeded`；可重试失败或暂停回到 `queued`，不可重试失败进入
`failed`，取消进入 `cancelled`。recipe 固定顺序：plan → implement → verify → review。

暂停语义：

1. 与领取/完成竞争时，以同一交付行锁决定先后。
2. 暂停先提交：撤销正在运行的租约、提高 epoch、关闭尝试；晚到完成/心跳拒绝。
3. 完成先提交：已接受的结果保留。调度器可记账和排队下一步，但暂停时不能领取。
4. 最后一个结果已接受时，调度器可以完成记账并收敛为模拟终态，即使随后发生暂停。
5. 恢复会重新领取。已领取的次数不退回，反复暂停不能绕过 3 次预算。
6. 暂停不冻结整体时限；需要更长运行时必须新增明确策略，而非无限延长。

取消先于 outbox 消费提交时，消费者不得建立新的可执行阶段。
若某操作与取消同时发生，可能返回 revision_conflict；客户端获取新快照后重新决策。

## 5. 原子性与幂等

每个状态变更、对应事件和 outbox 行在同一个数据库事务提交。
`actor + Idempotency-Key` 用事务 advisory lock 串行化；收据摘要包含 actor、目标操作和
校验规范化后的请求。同 key 同摘要返回原响应，不同摘要返回 409。
键是 actor 范围内全局唯一，不能在不同路由复用。

Outbox 至少一次投递；inbox 的 `consumer + event_id` 唯一约束与下一任务插入、outbox
确认处于同一个事务。进程在提交前退出则全部回滚，提交后再次读取不会重复推进。
这不是对外部系统的“全局 exactly once”承诺。外部写入需要自身幂等键、回执和对账。

失败命令回滚，不保存失败收据；相同 key 重试时会重新校验当前状态。
已成功提交的完成命令可以原样重放收据，即使之后租约失效或交付被取消；
这只返回历史确认，不产生新副作用。

## 6. 租约、恢复与预算

始终先锁 Delivery，再锁 Job。领取按创建时间选可执行交付，使用 `FOR UPDATE SKIP LOCKED`。
不同交付可并行，同一交付的领取、控制和完成串行。

完成/心跳需同时满足：交付未终结、active、未超过整体截止时间；Job 正在运行；
Worker 身份、租约 token、epoch 匹配；租约未过期。成功结果还必须匹配 step 与输入 digest。
数据库时间为判定依据，不信任 Worker 的本地时间。

默认租约 30 秒；每阶段最多 3 次领取；交付 1 小时。失联 Worker 的租约到期后，下一次
领取关闭旧 Attempt 并提高 epoch。没有 Worker 时，过期 Job 会留待重领，直到整体超时
由独立的 deadline 扫描终结。API 停机期间时限继续计算，恢复后扫描逾期交付。

调度循环每批最多 100 条，事件失败保留待重试并记录不含请求正文的错误标识。
M1 尚无死信管理 UI、重试退避指标或告警；不得作为无人值守生产调度器。

## 7. 可观察性

项目和交付快照各由单条 SQL 构造，避免读取到半次事务状态。事件 sequence 只用于
快照内排序，**不作为跨事务可靠增量游标**；ID 分配顺序不等于提交顺序。
操作台每两秒拉取选中交付。M1 不提供 SSE 或增量同步承诺。

日志仅记录请求 ID、事件名称、Job ID 和错误代码，不输出正文、令牌、SQL 参数或连接串。
交付快照隐藏 lease token，控制 API 与 Worker API 使用不同密钥。

## 8. 安全与权限

当前只允许 loopback，本地单管理员信任模型。固定 Worker 身份由服务端配置，
不是请求体任意提供；多个模拟 Worker 共享一个身份，仍用每次领取 token 与 epoch 防冲突。
控制令牌能访问所有项目，不是多租户 RBAC；数据库所有者也不是受限制的 Worker 身份。

HTTP 限制 64 KiB 请求体、15 秒请求时限，严格 JSON、路径 ID 和 schema 校验；
不提供 CORS，拒绝 cross-site fetch，控制台有严格 CSP，用户文本用 textContent 渲染。
密钥只在私有 `.env` 或运行环境中存在，不进入源码、API 响应、截图或日志。

真实接入前必须完成：多用户认证/授权、连接器最小权限、项目范围强制隔离、SSRF/链接读取策略、
文档中的 prompt injection 防护、独立执行环境、秘钥代理、审计保留和速率限制。
消息和 PRD 只能作为数据，不能直接授权工具调用。发布/外发/删除权限不得由模型输出授予。

## 9. 运维与已知限制

- `.env`、数据库卷不在 Git 中。迁移附校验和，已应用内容变更会拒绝启动。
- 单一迁移版本用于第一版，后续应追加迁移，不编辑已发布文件。
- 停库保留数据，删除卷会导致不可恢复丢失，正常流程不提供清库命令。
- 未实现收据/事件保留清理；空轮询也生成收据。只适合有限时长的本地试点。
- 项目列表最多 100 条；其他快照没有分页。大数据量和长期运行前必须补分页、归档和压测。
- UI 创建来源、需求、就绪与交付是多个独立命令，不是全局事务；失败时先查看项目快照，
  不要盲目重复提交。HTTP 客户端在网络重试中复用幂等键。
- 不做通用 DAG、拖拽编排、多仓库提交、真实 MCP、模型调用或发布。
- 当前没有生产备份恢复演练，不应导入敏感公司数据。
