# 分阶段实施与验收

## 原则

围绕单个真实需求建立一条可信闭环，然后逐步扩大自动化范围。
不能把三个 Prompt 串联等同于工程平台；状态、权限、证据和恢复必须由确定性代码管理。
产品负责规格，开发负责候选实现，测试负责独立验证；平台负责准入、调度与审批。

## M1：本地可靠调度底座（本次代码范围）

已实现的功能范围：

- 严格需求/命令/模拟结果合同与机器可读 schema。
- 本地单管理员项目、来源、不可变需求快照和需求就绪校验。
- PostgreSQL 持久化、固定 recipe、事务事件、outbox/inbox 和命令收据。
- 独立 HTTP 模拟 Worker、任务租约、心跳、epoch、有限次数和总时限。
- 暂停、恢复、取消、版本冲突与失效结果隔离。
- 本地操作台、CLI demo 和自动化测试入口。

验收标准：

| 编号 | 通过条件 | 对应自动化覆盖 |
| --- | --- | --- |
| M1-01 | 同一命令并发提交只创建一份数据/事件/收据 | integration：command/event/outbox |
| M1-02 | 同来源版本去重，变更正文不得静默覆盖 | integration：source versions |
| M1-03 | 无验收覆盖、跨项目来源、未就绪和错摘要被拒绝 | contracts + requirements integration |
| M1-04 | 多个 Worker 竞争只有一个有效租约 | concurrent workers |
| M1-05 | 每阶段成功仅建立一个下一阶段 | outbox crash/redelivery |
| M1-06 | 领取超时、暂停、取消后的结果不能推进 | expired leases + pause/cancel |
| M1-07 | 任务失败和 Worker 失联有有限预算 | retry budget + final lease |
| M1-08 | 已持久化结果由新实例继续调度 | four-stage/new connections |
| M1-09 | 模拟状态不能冒充真实完成或真实测试证据 | strict schemas + end-to-end |
| M1-10 | HTTP 认证、JSON、大小、幂等和输入边界有效 | HTTP tests |

M1 不等于连接器能力验证完成，也不等于整个原始平台设计完成。

## M2：来源接入与产品角色

交付：只读消息适配器、只读文档适配器、来源归档与需求草案生成。

首先明确：允许接入的会话/空间、身份、读取范围、敏感数据保留期限、历史回补窗口。
逐个列出 MCP 实际能力：搜索/读取/分页/编辑检测/删除检测/稳定 ID/限流/鉴权/失败行为。
没有稳定游标时使用来源 ID + 重叠时间窗口 + 回扫，不假设轮询能捕获全部修改和删除。

产品角色输入：来源快照及授权上下文。输出：范围、需求条目、验收方法、风险、阻塞问题。
信息不足停在待澄清，不得猜测后标记 ready。模型输出经 schema 和业务规则双重检查。
引入新 revision 时必须明确旧交付失效、继续或取消策略，不悄悄替换已绑定的输入。

验收：重复拉取不重复建需求，断线回补可对账，文本注入无法获取新工具权限，来源修改有
可审计新版本，未授权会话不读取，待澄清需求不能进入开发。

## M3：单仓库开发执行

交付：Project Manifest、只读仓库索引、开发计划、隔离执行环境、候选变更和审查请求。

Manifest 由管理员批准：仓库、基线提交、允许目录、安装/构建/测试命令、禁止操作、
依赖网络范围、资源/时间预算。命令用结构化配置和白名单，不执行 PRD 中的任意命令。
对三个参考项目分别建立 Manifest，不共享隐式目录、依赖或测试约定。

每个 Job 独立工作区，记录基线 SHA、最终 SHA、完整 diff、依赖锁文件和执行环境。
范围检查必须比较基线到最终提交的差异，不能只看未提交工作区变更。
产品角色不能直接改业务代码，开发角色不能批准自己的测试与发布。

验收：越界改动被拒绝，已提交的越界变更仍被检出，取消会终止执行环境，工作区不污染，
冲突和测试环境缺失不能被伪装为完成；未审批不自动合并或推送主分支。

## M4：真实测试与交付证据

交付：测试角色、项目 GateProfile、结构化 GateResult、EvidenceBundle 和人工复核页。

每个需求条目映射至少一个验收条目；每个验收条目映射自动 gate 或明确人工检查。
GateResult 必须有状态、命令身份、退出码、输入 SHA/digest、环境、时间和证据摘要。
人工 gate 未确认、测试跳过、没有环境、证据摘要不匹配均不能获得候选准入。

测试从干净候选环境独立执行，不接受开发 Worker 自报 PASS，也不只匹配 stdout 字符串。
失败回到开发需要有限修复预算；超限转人工，不开启无穷开发—测试循环。

验收：测试必须针对准确候选 SHA；改变需求/代码/环境使关联证据失效；红灯、缺证据、
未执行和待人工检查准确区分；完整回归与增量测试的适用范围可追溯。

## M5：外部协作与有限自动交付

交付：外部任务关联、审批队列、受控消息反馈和可对账的写入记录。

任务系统、公司消息、Git 写入都属于独立副作用。每种副作用配置范围、审批要求、幂等键、
回执和故障对账。自动创建任务或发送消息不代表可自行扩大接收人、频道、仓库或发布范围。
默认人工批准合并和发布；只有经过多轮稳定验证的低风险 recipe 才逐步降低审批频率。

验收：权限拒绝可见、同一外部动作不重复、部分成功可恢复、审批与证据版本绑定，
操作人能一键暂停相关任务并查看受影响外部状态。

## 生产门禁

多用户身份和项目授权、密钥管理、执行沙箱、审计和数据清理、备份恢复、容量/性能、
监控告警、死信处理、供应链安全、灾难演练全部完成后，才讨论长期无人值守。
具体模型、执行供应商和连接器认证由部署环境选择；本仓库目前不绑定外部模型服务。
